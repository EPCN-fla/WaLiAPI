# RAG 时间预算与检索优化

`/api/kb/ask` 可显式指定整次问答预算和关键词降级。省略新参数时保留历史渠道超时及正常、空结果语义，授权撤销与拒绝的即时复核已加强；直接聊天、入库的渠道超时不变。此修改没有数据库迁移、依赖升级或索引格式变更。

```json
{
  "kb_id": "已授权的知识库 ID",
  "question": "需要检索的问题",
  "model": "已授权的回答模型",
  "search_mode": "hybrid",
  "timeout_ms": 20000,
  "allow_keyword_fallback": true,
  "diagnostics": true
}
```

`timeout_ms` 服务端限幅为 100 至 120000 毫秒。权限检查、查询改写、Embedding、检索、重排、回答、响应校验共用绝对截止时间。API Key 执行链的每次发送及正文读取受渠道上限与阶段剩余时间共同限制，Key 轮换、跨渠道尝试和 Retry-After 不会重置预算。API Key RAG 路径中，传输失败可继续受限尝试；达到渠道或阶段超时后停止模型重试。显式预算内，该执行链的 401/403、402、结构化额度拒绝终止；上游限流按 Retry-After 在剩余时间内尝试。不会通过自由文本推断额度。

阶段上限以原始总预算计算：改写 10%、Embedding 40%、检索 20%、重排 10%，回答使用剩余时间并为结束处理留出 1%。非必要的改写、重排可恢复失败时保留原查询或排序；权限与额度拒绝终止。20 秒请求中 Embedding 最多消耗 8 秒，单次检索 scope 上限为 4 秒；重叠 FTS 与后续向量查询分别受该上限约束，并共用总截止时间。整体耗时不是阶段耗时的简单相加，这些是初始策略。

`allow_keyword_fallback` 默认关闭，仅作用于指定知识库的 hybrid 问答。API Key 请求先核对当前知识库、模型、渠道和额度权限，允许 FTS 与 Embedding 等待重叠；Embedding 超时、传输或协议等可恢复失败时，复用本次关键词结果。降级前重新核验权限，回答前和回答后复核知识库授权；回答后的检查不把本次合法消费刚达到额度误判为失败。鉴权、额度和 HTTP 429 错误不直接触发关键词降级。成功响应增加 `retrieval_mode` 和可选 `degradation_reason`，只有显式启用此功能才返回这些字段。

显式预算、降级或诊断请求要求非空检索片段、非空答案和实际发送给模型的来源。未带新参数的普通请求仍保持历史空结果/空答案语义。`diagnostics` 仍是显式开关。普通 REST 问答也通过服务端生成的 `x-request-id` 关联阶段、SQL 和物理尝试日志；本次新增阶段、SQL、物理尝试的结构化日志不记录 Key、提示词或上游正文，既有安全审计请求日志保持原逻辑；查看 SQL 与索引的分段耗时需要启用 `RUST_LOG=debug`。API Key MCP 问答支持相同新参数。管理员 REST 可使用总预算；内部 Embedding 的字符串错误仍保守拒绝降级，尚未将其改成完整的类型化失败接口。管理员的回答、改写和重排仍走历史 proxy 渠道循环，受外层阶段与总截止时间约束，尚未统一其物理尝试分类和 Retry-After 策略；单个渠道超时仍可能继续下一渠道。桌面 IPC 和管理员 MCP 沿用原参数接口。

HNSW 检索改为在同一个 SQLite 读事务中读取完整有效 ID/维度集合、检查索引、按候选 ID 读取正文及 metadata。正常命中不再把整库正文和 embedding BLOB 传回应用。仍检查 KB、ready 状态、embedding_revision、维度、完整 ID 集合和过期状态；同数量替换也会回退。索引缺失或过期时，同快照完整读取向量一次并精确扫描，不加 LIMIT 截断。旧切片的 `embedding_dim=0` 时保留解码后的维度兼容。

检索中的索引读盘、解码、骨架修复及计算放入最多四个后台任务；入库的索引构建保持原路径。future 被丢弃时通过本地取消标记停止后续工作；阶段截止也会被后台检查。同步文件读取和单次反序列化无法在任意字节处中断，后续阶段会检查取消。FTS 的遗留 NULL 投影回填仅处理当前 KB，保留中文分词、CAS 和中断恢复；无积压时只是空检查，没有每题重建 FTS。检索排序、融合算法与当前 KB 过滤后再 LIMIT 的语义保持。

本次没有实现常驻索引缓存、查询向量 TTL 缓存或在途合并。索引缓存需要可靠 generation，覆盖新增、删除、同数量替换、版本切换、事务回滚和原子文件替换；查询缓存还需实际模型/上游身份、维度、授权范围及独立取消语义。重复问题缓存也不能解决不同题首次 Embedding 的长尾，暂不引入未经验证的共享状态。索引目录仍沿用历史 `dirs::data_local_dir()/waliapi/hnsw_indexes`，`--data-dir`/`WALIAPI_DATA_DIR` 不改变此路径，同 KB ID 的跨实例仍可能共享索引；本次未重构数据目录传递。

取消证据分层记录：handler future 被丢弃、到 mock 上游的 TCP 关闭、真实入站 HTTP 断连传播是不同验证。本次在真实 Axum 服务和独立 SQLite 副本上实测三种请求（无预算、20 秒预算、20 秒预算加降级）：客户端 100ms 取消后，上游本机连接于 67 至 92ms 关闭，handler 和物理尝试记录取消终态；随后 7 秒仅有一次物理请求，无下一 Key 或回答。1 秒预算的慢上游测试还验证了 Embedding 截止后无降级时直接失败、开启降级后回答在剩余预算截止且无后续尝试。关闭本地连接不能证明供应商停止计算或计费；已完成的子请求会保留实际用量，未收到完整 usage 的取消请求不能据此推断零费用。

## 验证与性能

后端全量回归 1246 项通过，另显式运行的 SQL fixture 测量通过；跳过一项基线连续失败的 Antigravity 浏览器登录测试，未将其计作通过。桌面库检查、headless 测试二进制构建（未内嵌 Web）、未改动的前端桌面/Web 基线构建通过；未执行完整安装包发布。相同无桌面 feature 的 Clippy 基线 434 条诊断 / 147 种告警，最终 432 / 146，无新增告警；仅消除检索代码的一项旧告警。改动文件格式与 diff 检查通过。真实对照使用隔离服务、相同私有知识库快照、模型及 63 道不同题，官方答案仅在本地评分，不发送给模型。凭据只在内存转发器中使用，测试数据库不保存真实凭据。纯 RAG 与插件完整链路分开，模型兜底结果不混入纯 RAG 指标。完整链路通过当前插件生产 handleChat 的隔离 VM 执行，关闭本地题库与联网，不修改用户 Chrome、配置或插件。原始题目、官方答案及知识库正文只保存在本地测试材料，不随 PR 提交。

同模型 `deepseek-flash`、Embedding 模型 `Qwen/Qwen3-Embedding-8B`、同一知识库快照，纯 RAG 实测如下。成功 HTTP 响应不直接等于正确或有完整依据，均按官方答案评分。

| 实验 | 官方正确 | 客户端终态超时 | RAG 等待超时 | p50 | p95 | 纯模型兜底 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| v0.3.8 基线纯 RAG | 51/63（80.95%） | 12/63（19.05%） | 12/63 | 10.032s | 20.002s | 0 |
| 本次纯 RAG，显式预算与降级 | 61/63（96.83%） | 0/63 | 0/63 | 9.079s | 10.759s | 0 |
| v0.3.8 基线插件完整链路 | 58/63（92.06%） | 4/63（6.35%） | 19/63 | 12.984s | 34.473s | 19 次 |
| 本次插件完整链路，显式预算与降级 | 63/63（100%） | 0/63 | 0/63 | 9.146s | 10.472s | 0 |

本次纯 RAG 包含 31 次 hybrid 和 32 次因 Embedding 阶段预算耗尽的 keyword 降级；降级中 30 次正确、2 次未完整回答。配对结果为：基线超时的 12 题本轮全部正确；基线正确的 51 题中 49 题保持正确、2 题变为未完整回答。因此不能承诺准确性零回归，关键词证据不足时仍需拒答或由调用方按来源强度决定后续策略。

基线插件的 19 次纯模型兜底中，14 次正确、1 次错误、4 次整链超时；完整链路终态预算为 35 秒。本次插件轮包含 30 次 hybrid、33 次 keyword，63 次均通过插件现有证据启发式校验且来源非空。纯 RAG 中的 2 个未完整回答病例在插件轮未重现，模型输出和上游延迟随执行窗口波动，不能据此宣称降级不会损失答案质量。FTS 提前完成后复用结果可使诊断中的 retrieval 耗时显示 0ms，该值不能解释为 SQL 零耗时或纯 P1 性能收益。

纯 RAG 与完整链路的调用方均使用 20 秒 RAG 客户端等待上限；修复轮显式增加 `timeout_ms: 20000` 和 `allow_keyword_fallback: true`。现有生产插件尚未发送这两个字段，本次完整链路由 VM 的 fetch 验证适配器注入，handleChat 其他逻辑保持原样。使用旧参数的客户端不会自动获得阶段预算与关键词降级收益。

各轮按顺序执行，供应商负载与模型输出波动没有随机化控制；仅描述本次对照，不承诺长期生产收益。基线与修复均通过相同内存 relay 转发凭据，额外本机跳数与 Node HTTPS 客户端可能影响连接协商；相较生产 reqwest 直连的绝对性能外推未验证。基线本轮成功请求的检索阶段 p50/p95 为 31/64ms，未重现旧报告中的秒级 SQL 积压。测试数据库通过 SQLite 备份取得同一快照并脱敏，目标知识库五张相关表的逐行哈希与基线一致；所有生产数据库连接均只读，未调用生产服务接口。没有生产在线数据库起始全文件哈希，不能声称整个在线数据库文件字节未变。HNSW 仍读取历史目录的相同文件并核对哈希，未以隔离副本名义隐藏这一边界。没有实现查询向量或常驻索引缓存，也未做同题查询缓存的冷/热双轮测试；新服务进程的首题与后续不同题不能作为缓存命中收益证据。

首题和后续请求拆分如下，仅区分服务进程首请求与同进程的 62 个不同题；操作系统页缓存、供应商缓存没有受控清空。

| 基线纯 RAG | 14.736s | 9.960s | 20.002s |
| 本次纯 RAG | 2.944s | 9.086s | 10.764s |

SQL fixture 为 65 切片、1536 维、每片正文约 13600 字节、top_k=5，30 次同进程热读。旧查询传回数据约 1287325 字节，新身份加候选投影约 71060 字节；热读 SQL/快照 p50 1050→473 微秒，p95 1169→524 微秒，首次调用 1734→946 微秒。这是本地 SQL 投影测量，不包含索引、模型或操作系统冷缓存，不能外推到生产整体性能。

## 回滚

客户端去掉 `timeout_ms`、关闭 `allow_keyword_fallback` 即可回到历史 RAG 策略。完整回滚可撤销本 PR 的提交并重新构建；没有数据库迁移或持久索引格式变化，无需数据回退。生产安装包未在本任务中替换。
