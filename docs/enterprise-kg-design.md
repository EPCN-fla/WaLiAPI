# 企业知识图谱建设方案（轻量版）

> 目标读者：打算在现有 RAG / Wiki 体系上补一层知识图谱能力的团队。
> 原则：不做大而全的通用图谱，只为高频查询场景服务。

## 一、企业实际是怎么做的

先泼个冷水：企业里没有"AI 读文档 → 自动全抽 → 入库"这种一键流水线，踩过坑的团队都知道自由抽取的下场——实体重复、关系幻觉、图库变垃圾场。

实际做法是流水线 + 人工卡点，拆开就五步：

### 1. 先定 Schema（人工，最重的一步）

这是成败关键。先明确要回答什么问题，再倒推需要什么实体和关系。

比如客服场景要回答"这个订单属于哪个客户，客户的 VIP 等级是什么"，那 Schema 大概就是：

- 实体：客户、订单、产品、部门
- 关系：下单（客户→订单）、购买（订单→产品）、归属（员工→部门）

一张纸就能写完。不要贪多，实体类型控制在 10 个以内，关系类型 20 个以内。Schema 越大，后续抽取的噪音越大。

### 2. 文档接入与切块

复用现有 RAG 的解析和分块能力即可，没什么新东西。有一点要注意：切块粒度要比 RAG 稍大一些，因为抽三元组需要上下文，切太碎会把"张三是李四的上级"这种句子和人物介绍切开。

### 3. LLM 受约束抽取

这是和"AI 自由分析"最大的区别。prompt 里把 Schema 灌进去，要求模型只输出 Schema 内的实体类型和关系类型，格式强制 JSON：

```json
{"head": "张三", "head_type": "员工", "relation": "归属", "tail": "研发部", "tail_type": "部门", "evidence": "原文片段"}
```

要点：

- 带 `evidence` 字段，方便审核和溯源，没有原文支撑的三元组直接扔掉
- 一次抽一个 chunk，别整篇文档一起喂
- 温度调低，便宜模型（DeepSeek / GPT-4o-mini 级别）就够，这块是纯批量活

### 4. 实体对齐（工作量最大、最容易被低估）

"华为"、"HW"、"华为技术有限公司" 会抽成三个节点。不做对齐，图就散了。

务实做法分两层：

- **规则层**：别名表 + 标准化（去公司后缀、全半角统一），能解决 70%
- **相似度层**：剩余的用 embedding 算相似度，超过阈值的多半是同一实体，拿不准的进人工队列

人工队列不用怕，跑完第一批文档后增量会很少，是阶段性工作不是常态工作。

### 5. 入库与运营

- 图存储：小规模（百万节点以内）Neo4j 社区版就够，别上来就上 Nebula / JanusGraph
- 每条边带来源（哪个文档哪个 chunk），文档更新时只重抽受影响的 chunk，做增量更新
- 抽取失败的、低置信度的进审核队列，定期人工清一下

## 二、图谱和 RAG 怎么配合

不要用图谱替代 RAG，两者解决的问题不同：

| 问题类型 | 用什么 |
|---|---|
| "退货政策是什么" | RAG（事实性检索） |
| "A 公司的竞争对手的投资方还投过谁" | 图谱（多跳关系） |
| "我们产品线里哪些模块依赖这个组件" | 图谱（结构查询） |

常见集成方式：查询先过一层判断，看问题是否涉及多跳关系。涉及的走"实体识别 → 图查询 → 拿到相关子图 → 子图内容作为上下文再交给 LLM"，不涉及的走原有 RAG。图查询的结果最后也是拼成文本上下文，不需要前端展示图。

如果想再省事，直接参考 Microsoft GraphRAG 的做法：实体抽取 + 社区聚类（Leiden）+ 每个社区生成摘要，全局性问题按社区摘要回答。它的 prompt 设计可以直接抄。

## 三、落地节奏建议

1. **第一周**：选一个高频场景（比如客服工单），写 Schema，人工标注 50 条样例三元组当评测集
2. **第二周**：跑通"文档 → 抽取 → 入库"管线，用评测集量抽取准确率，低于 85% 先调 prompt 别急着扩量
3. **第三周**：补实体对齐，人工清一遍审核队列
4. **之后**：接进现有 RAG 查询链路，按 badcase 迭代 Schema

## 四、几个提醒

- **别追求全自动**。Schema 设计和实体对齐的把关是人工工作，工具再好也省不掉，但可以做得很轻
- **别用图谱存所有事实**。图谱只存"关系"，属性类的细节（订单金额、时间戳）留在原文，边上放个指向原文的引用就行
- **量力选型**。日均百万级文档以下，Neo4j + 一个定时抽取脚本就是全部技术栈，别被大厂方案带偏

一句话：企业做这事的核心不是"让 AI 抽得多"，而是**让 AI 抽得准、抽得可控，人只在 Schema 和对齐两个卡点出手**。
